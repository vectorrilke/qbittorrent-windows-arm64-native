# Workflow change log

Brief notes on every change to `.github/workflows/build-arm64.yml`, newest first.

- **Static build: fix link failure and keep the Qt cache (`build-static.yml`):** run 37000306177 got through Qt, libtorrent and the qBittorrent compile but failed at link with 4 `LNK2005` duplicate symbols (`QByteArray::isNull`, `QLocale::QLocale(const QString&)`, `QString::toLongLong`, `QBasicTimer::start`) between `Qt6Core.lib(removed_api.cpp.obj)` and qBittorrent's objects. Cause: qBittorrent's `CommonConfig.cmake` sets `QT_DISABLE_DEPRECATED_UP_TO=0x060500`, so the Qt 6.10 headers inline those functions while static Qt6Core also defines them. Added a step that removes that define from the cloned source (static build only). Also replaced `actions/cache` with `cache/restore` + `cache/save` right after the vcpkg, Qt and libtorrent builds, because the failed run lost the compiled static Qt (the old action only saves when the whole job succeeds). Verified: run 37005100056 linked, passed the self-contained check and smoke test, and the exe was confirmed working by the user.
- **Release workflow, reusable builds:** added `release.yml` (manual run; builds both variants in parallel and publishes one release `v<version>-arm64` with the zip and the static exe; `rc`/`beta` versions become pre-releases; the zip is still published if the static build fails). Renamed `build-arm64-5.2.3.yml` to `build-zip.yml` and `build-arm64-5.2.3-static.yml` to `build-static.yml`, and made both callable (`workflow_call`, with version outputs) while keeping `workflow_dispatch`. Removed their own publish step and the `release` input. Artifacts are now `qbittorrent-zip` (`qbittorrent_<ver>_arm64.zip`) and `qbittorrent-static` (`qbittorrent_<ver>_arm64_static.exe`), and the version is derived from the tag. Deleted `build-arm64.yml` (5.3.0rc1): it only differed from the zip build in its defaults, so it can be run from `build-zip.yml` with the 5.3.0rc1 inputs. Untested on GitHub; the release step has not run yet.
- **New workflow `build-arm64-5.2.3-static.yml` (single exe):** same 5.2.3 / libtorrent 2.0.13 / Boost 1.91.0 defaults, but Qt 6.10.3 (qtbase, qtsvg, qttools) is built from source as static libraries (`-static -static-runtime`, no OpenGL/OpenSSL; TLS via Schannel) and cached. Everything else is built with the static CRT (vcpkg triplet `arm64-windows-static`, libtorrent `static_runtime=ON`, qBittorrent `MSVC_RUNTIME_DYNAMIC=OFF`), so `qbittorrent.exe` has no Qt/VC++ DLLs and needs no `qt.conf`. Adds a step that fails if the exe imports non-system DLLs, and a non-blocking smoke test that starts the exe for 20 s. Output is a single `.exe` instead of a zip. The first run is slow (Qt compile); later runs reuse the cache. First run failed at link (fixed in the entry above).
- **New workflow `build-arm64-5.2.3.yml`:** copy of `build-arm64.yml` with defaults for the 5.2.3 "qt6 lt20" build: tag `release-5.2.3`, libtorrent `da7a68a440` (2.0.13), Qt 6.10.3, Boost 1.91.0. Added because the 5.3.0rc1 build could not download from the user's private tracker while 5.2.3 worked for them. Only the version defaults and the name differ; `build-arm64.yml` is unchanged.
- **Qt install:** use aqt host `windows_arm64` instead of `windows`. Native ARM64 Qt 6.11.2 is published under `windows_arm64/desktop` on download.qt.io, and with host `windows` aqt looked under `windows_x86` and failed with "Failed to locate XML data for Qt version '6.11.2'". The base install already includes qtsvg and qttools. (Run 36993926218 failed here.)
- **Boost download:** fetch `boost_*.tar.gz` instead of `.zip` and extract with `tar -xzf`. The zip made `tar` fail with "Archive entry has empty or unreadable filename". (Run 36993783301 failed here; fixed in 86595ea.)
- **Initial version:** workflow created from PLAN.md. Version env vars at the top, native `windows-11-arm` build with MSVC, Boost headers, vcpkg OpenSSL/zlib, Qt via aqtinstall, static libtorrent, qBittorrent, `windeployqt`, zip artifact, optional release.
